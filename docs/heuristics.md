# gaffy layout heuristics

Rules that decide which functions are drawn, where, and how call lines run. Generated by `npm run heuristics` from [scripts/heuristics.ts](../scripts/heuristics.ts); the same graph opens in gaffy as [heuristics.gaffy](heuristics.gaffy) (a static view: no language server).

Stages, in this order on every redraw: reveal => grouping => rows => placement => settle => call lines, then the view. Order of the rules and their kinds: [terms.md](terms.md#rule-order); terms: [terms.md](terms.md); pictures: [examples.md](examples.md).

Reading the graph: a function calls the functions and rules below it in code order (call line). In the picture and in gaffy, a function opens its code, a rule or decision opens its explanation below; in gaffy, right click a line > Go to Call Site opens the rule's code line.

## Reveal

### h01_first_revealer

**First opener.** One layer at a time: sides open in seed order, and each function's neighbours by call line. The first function to show another is its opener: the opener fixes the side the shown function may open and the level an arrowhead into it closes.

Code: [reveal.ts:69](../src/core/reveal.ts#L69), in `reveal`.

### h02_call_depth_by_path

**Call depth by path.** Full layout: a function's level is its fewest calls from a seed (shortest) or its most calls with loops ignored (longest).

- Chosen by: Options > Call depth by (view.depthRule).

Code: [reveal.ts:88](../src/core/reveal.ts#L88), in `revealDepth`.

Code: [boxes.ts:53](../src/core/boxes.ts#L53), in `boxTree`.

## Rows

### h04_sort_key

**Sort key.** Ties are broken by (file path, definition line, name).

Code: [scene.ts:89](../src/core/scene.ts#L89), in `sortKeyOf`.

### h05_marker_row_first

**Marker row first.** A `└─>>` marker row has the empty sort key: it is always the first row hanging under its function.

Code: [scene.ts:212](../src/core/scene.ts#L212), in `buildScene`.

### h06_root_order

**Root order.** The top functions of a block (no parent) are ordered by your Move Up/Down order, then the rows of their callers outside the block (h13_caller_alignment), then seed order, then h04_sort_key.

Code: [layout.ts:93](../src/core/layout.ts#L93), in `layout`.

### h07_child_order

**Child order.** The functions hanging under a parent are ordered by your Move Up/Down order, then call line, then h04_sort_key.

- Alternatives (Rules panel): `line` (default): call line, then sort key; `definition`: definition order (h04_sort_key).

Code: [layout.ts:102](../src/core/layout.ts#L102), in `layout`.

### h08_row_order

**Row order.** Rows follow a depth-first walk from uncalled functions (seeds first where a loop has no entry). Every caller lies above its , except calls back up a loop, which show as `↻` tags.

Code: [layout.ts:152](../src/core/layout.ts#L152), in `layout`.

### tree_parent_rule

**Decision: parent rule.** Chooses the parent of a function, the caller it hangs under (`└─>`): `joint` (Options > Parenting, the default) for a function with two or more callers in its block, else `dfs` or `nearest`.

- Chosen by: Options > Parenting (view.parentRule).

Code: [layout.ts:173](../src/core/layout.ts#L173), in `layout`.

### h09_joint_parent

**Shared entry from the left.** Two or more callers in the block: a caller right above shares its branch (`├───┴─>`); otherwise the function takes no parent and every call enters it from the left through one trunk (`┌──┘`, `└─>`), turning in on the row above it.

- Chosen by: Options > Parenting (view.parentRule).

Code: [layout.ts:173](../src/core/layout.ts#L173), in `layout`.

### h10_dfs_nearest_parent

**Parent: first or nearest caller.** `dfs`: the caller that first reached the function in the walk. `nearest`: the closest caller above whose stem no row in between would cross. Without a parent, a function is indented under its nearest caller.

- Parameter `h10_dfs_nearest_parent.indent` = 4, range [3, 16]: columns from a tree parent to its child.
- Chosen by: Options > Parenting (view.parentRule).

Code: [layout.ts:190](../src/core/layout.ts#L190), in `layout`.

### h11_port_row

**Exit row.** A function whose end receives a trunk and that also sends calls by trunk or path search gets an exit row below it; its calls leave from there, so an arriving and a leaving line never share a row.

Code: [layout.ts:234](../src/core/layout.ts#L234), in `layout`.

### h12_lane_packing

**Trunk columns.** The trunks of a block are placed shortest first, each in the first free column right of every label it passes, `gap` columns from the trunks beside it.

- Alternatives (Rules panel): `shortest` (default): shortest trunk first; `longest`: longest trunk first.
- Parameter `h12_lane_packing.gap` = 2, range [1, 8]: columns between trunks with overlapping rows.

Code: [layout.ts:261](../src/core/layout.ts#L261), in `layout`.

## Placement

### h13_caller_alignment

**Caller alignment.** Each top function of a block takes the earliest row of its callers outside the block still free, so the call runs level.

- Switch (Rules panel): off: the top functions of a block one row after another from the top, not at their callers' rows.

Code: [place.ts:142](../src/core/place.ts#L142), in `placeBlock`.

### h14_monotone_rows

**Rows only go down.** A row's place is the larger of "row above + 1" and its preferred row (h13_caller_alignment); the row where a shared entry turns in (h09) stays right above its function. Rows skip the cells of a locked function of the block (locks are absolute); the functions hanging under it move with it.

Code: [place.ts:155](../src/core/place.ts#L155), in `placeBlock`.

### h15_block_descent

**Block slides down.** A block that would overlap something already placed slides down until clear.

- Switch (Rules panel): off: blocks keep their row over earlier groups.
- Parameter `h15_block_descent.flag` = 12, range [1, 1000]: rows of descent that flag the decision.

Code: [place.ts:179](../src/core/place.ts#L179), in `placeBlock`.

### h21_moved_function_descent

**Moved function slides down.** A moved, unlocked function with the functions hanging under it slides down until its labels clear the other labels of its block. A collapsed group moves and locks as `collapsed:<key>`, apart from its expanded function, so expanding it returns to the layout before the collapse.

- Switch (Rules panel): off: moved functions keep their row over labels of their block.
- Parameter `h21_moved_function_descent.margin` = 2, range [0, 8]: cells kept between labels of one row.
- Parameter `h21_moved_function_descent.flag` = 4, range [1, 1000]: rows of descent that flag the decision.

Code: [place.ts:230](../src/core/place.ts#L230), in `placeBlock`.

### h16_item_order

**Group order.** Within a group, its block and subgroups are placed locked ones first, then callers before  (ties by h03_box_order).

Code: [place.ts:307](../src/core/place.ts#L307), in `placeBox`.

### h17_item_column

**Group column.** A subgroup goes right of the rightmost earlier subgroup or block calling into it, plus `channel` columns and 1 per function the calls enter; otherwise at the left edge of its group.

- Switch (Rules panel): off: subgroups at the left edge of their group, not right of the groups calling them.
- Parameter `h17_item_column.channel` = 4, range [1, 16]: columns between a calling group or block and the group it calls.

Code: [place.ts:356](../src/core/place.ts#L356), in `placeBox`.

### h18_item_row

**Group row.** A subgroup starts at the row of its first placed caller, else below the unlocked subgroups placed before it.

- Switch (Rules panel): off: subgroups stacked below the earlier ones, not at their callers' rows.

Code: [place.ts:362](../src/core/place.ts#L362), in `placeBox`.

### h41_called_below

**Called group below its caller.** One layer at a time: a group called from a single sibling group, on screen because the callers of one of its functions were opened, hangs below the caller's group, placed for the calls into it: one caller with nothing hanging under it and no label below it in its group drops its call straight down, so the group's content sits one indent right of it (`caller()` over `└─> f()`); otherwise the group sits right of the callers' label ends and a channel, so their calls run right, down into one trunk, in from the left. Then up to `tries` cells around this plan are tried, nearest first: for each, the calls touching the group are routed (everything else an obstacle), and the cell with the least route cost plus `move` per cell from the plan is kept. What was drawn before stays. Replaces h17_item_column and h18_item_row for that group; h20_unmoved_box_descent still keeps it clear of other groups.

- Switch (Rules panel): off: the group sits right of its calling groups, at the caller's row (h17_item_column, h18_item_row).
- Parameter `h41_called_below.tries` = 6, range [1, 15]: cells tried around the plan; 1: the plan only.
- Parameter `h41_called_below.move` = 1, range [0, 10]: cost per cell between a tried cell and the plan.

Code: [place.ts:333](../src/core/place.ts#L333), in `placeBox`.

### item_state

**Decision: locked, moved or unmoved group.** A subgroup is placed by its lock, by its move, or by trial placement.

Code: [place.ts:383](../src/core/place.ts#L383), in `placeBox`.

### h19_lock_and_box_offset

**Moved or locked group.** A moved group is placed as if unmoved (at its trial row), then shifted whole by its move: labels, trunks and inner frames keep their places in its frame. A locked group shifts the same way, onto its fixed cell (frame corner).

Code: [place.ts:391](../src/core/place.ts#L391), in `placeBox`.

### h20_unmoved_box_descent

**Group slides down or right.** An unmoved group that overlaps an earlier one slides down until clear, by the distance from its top to below it, or right past it when that costs less (`down`, `right`, `cross`). A group whose frame a locked unit inside pins (locks are absolute) stops where a further slide gains nothing, flagged. An earlier group moved by a drag counts at its unmoved place, so a move never pushes unmoved groups down. Moved groups are exempt; h23_settle handles them.

- Switch (Rules panel): off: unmoved groups keep their trial row over earlier ones.
- Parameter `h20_unmoved_box_descent.flag` = 12, range [1, 1000]: rows of descent that flag the decision.
- Parameter `h20_unmoved_box_descent.down` = 1, range [0, 10]: cost per row of descent.
- Parameter `h20_unmoved_box_descent.right` = 0, range [0, 10]: cost per column of a move right past the overlapped item; 0: never right.
- Parameter `h20_unmoved_box_descent.cross` = 0, range [0, 10]: cost per call between other functions whose span the group would cover.

Code: [place.ts:403](../src/core/place.ts#L403), in `placeBox`.

### h22_frame_extent

**Frame size.** Tight frames (Options > Grouping > Tight, the default): a frame is its content's bounding box plus margin. Otherwise a frame keeps its group's unmoved corner and only grows. Grouping or ungrouping a namespace drops the moves inside it (`dropMovesWithin`): moves count from the group that held them.

- Chosen by: Options > Grouping > Tight (view.tight).

Code: [place.ts:452](../src/core/place.ts#L452), in `placeBox`.

### h38_frame_overlap

**Frame overlap.** Frames of sibling groups may overlap where their content does not. A group overlapping an earlier sibling's frame stays when no label, header or arrival cell of either lies within `margin` of the other's frame: h20_unmoved_box_descent and h23_settle test labels against frames, not frames against frames. Blocks (h15_block_descent) keep clear of other content. Labels never overlap.

- Switch (Rules panel): off: frames nest or stay apart: an overlapping group descends.
- Parameter `h38_frame_overlap.margin` = 1, range [0, 6]: cells kept between a label and a foreign frame border.

Code: [place.ts:408](../src/core/place.ts#L408), in `placeBox`; [settle.ts:54](../src/core/settle.ts#L54), in `settleMoved`.

## Settle

### h23_settle

**Settle moved units.** Every redraw, moved units whose labels or frames lie on other content, or whose frame touches another frame without a free row or column between (no corridor for call lines), go to the nearest clear spot, at most `rounds` rounds (the loop in buildScene). The move that displaces least goes first (distance × labels moved: a small unit yields to a large one); ties: groups before functions, then the smaller unit. Search: `range` cells around (vertical first), then straight lines up to `far`, never off the top or left edge. Locked units never move. Call lines are not considered.

- Switch (Rules panel): off: moved units stay where their moves put them.
- Parameter `h23_settle.range` = 12, range [1, 40]: Manhattan radius of the ring search.
- Parameter `h23_settle.far` = 80, range [0, 400]: cells of the straight-line search past the rings.
- Parameter `h23_settle.margin` = 4, range [1, 12]: cells between labels of one row.
- Parameter `h23_settle.rounds` = 3, range [0, 8]: settle rounds per redraw.
- Parameter `h23_settle.flag` = 12, range [1, 1000]: move length that flags the decision.

Code: [settle.ts:104](../src/core/settle.ts#L104), in `settleMoved`.

## Call lines

### h24_tree_lines_first

**Branches and trunks first.** Branches and the trunks of a block are drawn before path search; a branch between functions with different moves is searched instead.

- Switch (Rules panel): off: every call line by path search: no branches, no trunks.

Code: [grid.ts:360](../src/core/grid.ts#L360), in `buildGrid`.

### h25_routing_order

**Search order.** Calls are searched one at a time, each an obstacle for the calls after it: the order decides which call takes a free corridor and which must cross it. Straightened calls first, then by the chosen alternative: `row` (default), callers top to bottom, a caller's calls together in called order; `longest`, level calls shortest first, then the rest longest first; `shortest`, level calls, then the rest shortest first.

### h29_route_cost

**Path cost.** Path search: A* over (cell, heading), guided by the grid (Manhattan) distance to the arrival cell. Each step costs 1; +`border` entering a frame border, +`cross` crossing another call line, `bundle` along a line into the same called (joining its trunk) or along the caller's own lines, also where another line crosses them (calls of one caller leave as one bundle and split once), +`bend` per change of heading, +`adjacent` for a vertical step next to another call's vertical line. Never: label cells and padding, markers, reversing, running along a border, cells kept for another call. The first pass forbids running along or turning on another line; a second allows them at +`relaxAlong` and +`relaxTurn`. No path in both passes (`steps` search states): dashed.

- Parameter `h29_route_cost.bend` = 3, range [0, 100]: per change of heading.
- Parameter `h29_route_cost.cross` = 6, range [0, 100]: per crossing of another call line.
- Parameter `h29_route_cost.border` = 4, range [0, 100]: per frame border crossed.
- Parameter `h29_route_cost.adjacent` = 2, range [0, 100]: per vertical step next to another call's vertical line.
- Parameter `h29_route_cost.bundle` = 0.3, range [0.05, 1]: per step along a line into the same called, or along the caller's own lines, crossings included (joining it).

### h39_reroute
